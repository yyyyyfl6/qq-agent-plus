# 长期记忆与检索

记忆分两类：

- **人物印象**：按 QQ 全局保存，每条最多 300 字，带来源会话与观察时间；
- **会话交接**：按 chatKey 保存，记录当前话题、假设、证据、决定与下一步。

人物印象是“养鱼”的核心数据；检索入口是 `memory_query`。

## 检索

`memory_query` 新增 `query` 参数：

```json
{ "query": "上次说的那家面馆", "limit": 8 }
```

实现：

- SQLite FTS5（`data/memory/search.sqlite`）；
- 中文按单字 + 二元组切词，拉丁按词切词；
- FTS 候选再用覆盖率、FTS 排名、新鲜度重排；
- 支持 1 字、2 字、短句和混合中英文；
- 索引是派生数据，损坏不会影响 JSON 记忆正文；找不到索引时会退化为内存扫描。

索引是**词法检索**，不是向量语义检索：

- “面馆 / 新开的面馆 / 谁提过面馆”能命中；
- 换成完全没有共同词的近义表达（例如“餐厅” vs “面馆”）可能找不到；
- 需要真正的语义召回时，后续可接 embedding；当前版本没有默认开启，避免把记忆正文发给第三方。

## 可见性

检索结果在**读取侧**再按 `memory.visibility` 过滤：

- `perChat`：只返回来源含当前会话的印象；
- `hidePrivateInGroup`：群聊里不返回私聊来源；
- 来源会话字段不会交给模型，控制台人物记忆页仍可查看。

## 容量与保留期

默认值：

- 每人最多 **50 条**人物印象；
- 每条最多 **300 字**；
- 自动印象保留期 **0 天 = 不按时间过期**（升级老库不会清掉历史）；
- 控制台手写的 `manual` 条目永远不因上限/保留期被删。

管理员可以在「设置 → 记忆」改成：

- 每人 5–200 条；
- 保留 0–3650 天（0 = 不过期）。

超过条数上限时，优先保留 manual，再按最近观察时间淘汰自动条目。

## 实测容量

在本机用 100 人 × 每人 50 条（共 5,000 条）跑容量基准：

- 人物 JSON：约 1.3 MB；
- FTS 索引：约 4.5 MB；
- 首次检索（含建索引）：约 150 ms；
- 2,500 条时热检索：p50 约 11 ms、p95 约 15 ms。

所以百万级聊天记录不会进这个库；长期印象本身是“每人最多 50 条”的小数据。真正占空间的是消息库和媒体文件。

## 召回基准

`test/memory-search.test.mjs` 内置 14 条合成印象和 10 个查询，覆盖：

- 2 字关键词（面馆、周会、爬山、火锅）；
- 单字（猫）；
- 完整短句（汤有点咸、取快递）；
- 改述（那家新开的店、周末去哪儿、谁提过面馆）。

当前结果：**recall@3 = 10/10**。这不是通用语义评测，只证明词法/二元组检索对群聊里常见的“人 + 地点 + 事件”问法有效；完全换词的近义问法仍可能漏。

## 备份与恢复

`search.sqlite` 位于数据目录内，会随 `ops backup` 一起备份；它是派生索引，删除后下一次检索会自动重建。人物印象 JSON 才是权威数据。
