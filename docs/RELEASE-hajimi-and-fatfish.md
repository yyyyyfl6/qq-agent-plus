# hajimi and fatfish

开发分支为 `hajimi-and-fatfish`；发布 tag 使用 `hajimi-and-fatfish-<提交短 SHA>`，与上游版本命名分开。首次更新原修补版的 Release 名称和 tag，原 tag 与提交历史保留。

人格列表现在直接提供「新增人格」和「编辑人格」。在同一个编辑框里填写名称、选择已有预设、提供商和模型、设置自定义切换指令，点击「保存人格」立即保存。允许用户继续新增第三、第四个人格（最多 16 个），刷新后仍保留。旧鱼/猫快捷指令显示在对应人格里，可修改。

删除人格页重复的「API 与模型」和「添加自定义人格预设」入口，复用原有设置与目录。编辑人格保留用于定位历史的 ID，移除配置保留存档与记忆。人格保存与总结设置分别提交，会话列表读取失败不影响新增或编辑。

在最终模型请求前过滤不支持的附件，保留文字和兼容图片；Gemini 不再收到 GIF 原始数据，即使 GIF 转 JPEG 失败或旧历史中留有 GIF 也会过滤。已转换为 JPEG 的帧条继续使用。图片按魔数核对类型，工具结果与额外请求参数中的附件也检查；明确的 MIME 转换失败不再按临时 HTTP 500 反复重试。

异常通知的结果限制为 220 字符，加截断提示；图片/附件 base64 内容省略。通知保留异常编号与控制台处理入口，控制台仍可查看脱敏后的错误详情。

交接总结可独立选择提供商和模型，默认 deepseek-flash。摘要失败仍完成切换，日志、页面与 QQ 指令回执会显示脱敏的 HTTP/网络/配置原因，并区分关闭、无消息和空响应。

修复交接在组装首轮提示词时即失效的问题。当前人格任期内持续携带另一人格的摘要，静默首轮、失败重试、无状态会话和生命周期后续轮均保留；下次切换替换摘要。成功返回后才记首次送达时间。超长历史优先保留最近完整消息，摘要明确保留具体问题和回答；新人格可根据交接转述回答，仍不能假装亲历。不共享对方原始聊天记录。无消息或空摘要时 QQ 回执会说明没有生成交接。

修复同端点提供商跟随全局 Key 时出现空 Key/旧 Key 的问题；全局 Key 更新后跟随生效，跨端点缺少自己的 Key 时在发送请求前报错。

更新器部署前检查配置文件及目录读写权限。配置写入失败也继续发送待处理管理员通知；首页显示更新停止和错误原因。权限修复后需手动恢复自动更新。

测试账号改为虚构值，配置文档改为示例提供商 ID；既有运行配置和公开历史保持兼容。

## 升级与回滚

部署使用 fork 的已发布 `hajimi-and-fatfish-<提交短 SHA>` tag。先备份 data/config.json、聊天 SQLite 和 data/memory；此版本没有新增运行依赖，也没有迁移存储格式。

升级后刷新控制台页面，进入「人格」，点击已有条目的「编辑人格」检查预设、模型和指令，或点击「新增人格」创建新组合。默认未启用的实例仍保持关闭，需在「切换设置」启用并保存后才会响应切换。旧的空总结模型自动按 deepseek-flash 处理；需要原聊天模型总结的实例请明确选回该模型。

回滚到 v0.7.8 保留原数据；v0.7.8 不支持自定义预设引用、人格专属 commands 和新摘要诊断。使用自定义预设的实例应先恢复旧配置备份，再启动旧代码。

自动更新遇 EACCES/EPERM 时，将数据目录及配置所有权恢复为 Agent 的服务用户，确认其能读写配置，再到「控制 → 更新部署」手动恢复。不要以 root 重新部署。

服务器部署和真实 QQ 对话/在线模型验收由实例维护者执行。
