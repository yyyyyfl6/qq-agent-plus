# IP 查询 ip-info

**这个 IP 是哪儿的** —— 国家、省市、运营商、所属组织、ASN。
走 ip-api 免费接口，**不需要 Key**（免费层每分钟 45 次）。

## 能做什么

- **IP 和域名都行**：`8.8.8.8`、`github.com`
- **查归属**：国家、省市、运营商（ISP）、所属组织、ASN、反向解析
- **域名交给上游解析**（原因见下），各种部署下行为一致

## 群里怎么问

- 「8.8.8.8 是哪儿的」
- 「github.com 的服务器在哪」
- 「这个 IP 归属哪个运营商」+ IP

## 配置（可选）

- `endpoint` —— 换成**公网**的自建 / 镜像接口（内网地址会被宿主的网络守卫拦下）

```json
{ "plugins": { "settings": { "ip-info": { "endpoint": "http://ip-api.com/json" } } } }
```

## 边界

- **归属地是 IP 的登记信息**，不保证是服务器的实际物理位置（CDN / 代理会让它看起来在别处）——
  结果里会带这句提醒
- 不查内网 / 私有地址（`192.168.x.x`、`10.x.x.x`、回环等）
- 不做端口扫描、不反查域名列表、不查历史归属
- 接口是 `http://`（免费层只给 http），请求仍经宿主的网络守卫
- 只读，不能发言

## 关于域名解析（一个刻意的取舍）

ip-api 自己接受域名（它在服务端解析），所以这个插件**不在本地做 DNS**：

- 宿主在 Linux 上把插件进程放进**没有网络接口的命名空间**（见 `docs/PLUGINS.md` 的信任声明），
  那种环境里插件自己的 `dns` 解析会直接失败 —— 结果就是「能查 IP 却查不了域名」
- 把解析交给上游，插件对网络的唯一出口就只剩宿主的 `cap.http.request`

## 装

控制台左侧「插件」→ 安装 → 启用。手工：把本目录拷到 `$DATA_DIR/plugins/ip-info/`。
