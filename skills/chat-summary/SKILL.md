# 群聊总结

目标：让没跟上聊天的人用最短时间知道发生了什么，同时不把猜测写成事实。

步骤：

1. 先用 `get_recent_messages` 读取最近 30–80 条消息。不要只凭提示词里的【过去状态】就下结论。
2. 按“结论 / 分歧 / 待办”三类整理：
   - 结论：已经明确达成的事实或决定；
   - 分歧：有人不同意、还没定的事；
   - 待办：明确谁在什么时候要做什么。
3. 只写消息里出现过的人、时间、地点和数字。没有说清楚的就写“还没定”，不要补全。
4. 如果群里只是在闲聊，没有结论，就直说“这轮主要是闲聊”，不要硬凑三条。
5. 用机器人自己的口吻发，控制在 3–5 条短句；不要输出“以下是总结”这类客服腔。

边界：

- 不要引用私聊内容，也不要把其他群的记忆带进来。
- 不要评价群友的性格或关系，除非总结任务明确要求且消息里有依据。
- 不要为了显得完整而编造时间、地点或承诺。
